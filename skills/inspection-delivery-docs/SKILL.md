# 交付文档与验收用例（inspection-delivery-docs）

## 这个技能解决什么

交付物不只是能跑的程序，还包括**别人能核对的材料**：README 说清怎么跑、用哪个模型、有什么限制；测试结果表说清跑过什么、结果如何；演示用例说清现场按什么顺序演。本技能把这些固定成清单与句式，避免"文档看着齐全但关键事实缺失"。

## 什么时候用

- 收尾准备交付材料时；
- 别人问"你凭什么说模型真的调过"时（README 第五节 + 测试结果表 + 日志三处互证）；
- 提交前最后一次自检。

**不要**用它写营销文案，也不要代写客户侧 PPT 的视觉设计（美术层不归本技能）。

## 必备章节清单（README）

1. **包/产物清单**：每个包名、承担的能力词（逐字）、形态（插件/技能）、一句话职责。
2. **怎么跑**：依赖什么、放到哪里、需要什么服务（模型 provider / attachment / webServer）、自检脚本怎么执行。
3. **能力与工具一览**：工具名（ASCII）、每个工具做什么、调用示例。
4. **数据与存储**：数据根、表/文件、重置边界（清什么、留什么）。
5. **所有大模型调用及调用方式**（**硬要求，不许省**）：
   - 用到的 provider + model（逐字，如 `deepseek-official` / `deepseek-flash`）；
   - 调用方式：统一走宿主模型服务 `ctx.llm.stream({ provider, model, messages })`，**不自己带 key**；
   - 每类调用列出来：视觉判断（多模态，需模型声明 `image` 输入模态 + attachment 服务）、检查项生成（文本）；
   - 提示词版本标识（如 `vision-judge-v1` / `checklist-v1`）与涨版本规则；
   - 失败行为：不可达/未配置时返回哪些错误码、会不会降级（本单：**不降级成假结论**，改为排队）。
6. **限制与已知问题**：没做的（部署/登录权限/门店增删改/勾选表）、没实测的（明确写"未实测"）。
7. **License 声明**：本项目 License；引用了第三方内容时必须写清来源与许可。

## 测试结果表（**不得编造**）

每行一条实测，四列都要有：

| 用例 | 怎么跑（可复制命令/调用） | 实测值 | 结论 |
|---|---|---|---|
| 真视觉判断 | 调 `inspection_judge_photos`（真 provider/model） | 返回问题项 N 条 + 耗时 + usage | pass/fail |
| 看不清 | 用失焦/过暗照片同上一路径 | `findings:0`、`unreadable:1`（含原因） | pass/fail |
| 模型不可达 | 关 provider / 断网后提交 | 回执 `status:'queued'`、`judgementsProduced:0` | pass/fail |
| 定时器 | 看 `logs/scan-log.jsonl` 的两次 tick 时间戳 | 间隔 ≈ 配置周期 | pass/fail |
| 重置不污染日志 | 重置前后 `model_calls` 计数 | `dropped === 0` | pass/fail |

规则：
- 写进表里的每一行，必须能给出**那一次的实测值**（时间戳/计数/返回片段）；
- 没跑过的写"未实测"，**不许推测填空、不许把别人的结果抄进来**；
- 跑失败的如实写 fail 并说明卡在哪。

## 现场演示用例（按顺序，含动态性对照）

1. **达标态 vs 问题态对照**：同一家门店两次自查，一次没问题、一次有两条问题 —— 说明"不是固定模板输出的"。
2. **判断 → 整改要求 → 截止**：点开问题条目，看到依据文字 / 圈框（无坐标时是"标点 + 文字"）/ 处置建议 / 截止时间。
3. **真动作**：按「立即扫描」或等定时器，逾期项变逾期 → 催办 → 升级，看板时间线上出现痕迹。
4. **断网降级**：进离线 → 提交 → 只排队、不产生判断、日志条数不变 → 恢复后补判成功。
5. **模型调用可查**：打开日志面板，逐条对时间/模型/提示词版本/提交编号/请求摘要/响应摘要/耗时；**面板里不出现任何 key 或 Authorization**。
6. **重置**：重置后业务数据清空、`model_calls` 计数不变。

## 提交前自检（逐条打勾，缺一不可）

- [ ] README 五节齐，第五节写明 provider/model 与调用方式；
- [ ] 每个包的 `manifest.json` 的 `tools` 与代码注册名**逐字一致**、全部 ASCII；
- [ ] 能力词在产物里**逐字命中**（插件靠 `keywords`，技能靠 `description`）；
- [ ] 测试结果表里没有"未跑却写 pass"的行；
- [ ] 演示用例能按顺序走通一遍（含失败路径）；
- [ ] License 与第三方来源（如有）写清；
- [ ] 产物里**没有 key、没有 Authorization、没有真实品牌名**；
- [ ] 没做的功能在"限制"里显式列出（部署 / 登录权限 / 门店增删改 / 勾选表）。

## 边界与不做什么

- **不做部署**：删掉任何与部署加分相关的实现与文档章节。
- 不写营销文案、不做客户侧 PPT 视觉设计（美术层）。
- 他人内容（原则、表格、代码）**必须写明来源与许可**；来源说不清就不要写进去。
