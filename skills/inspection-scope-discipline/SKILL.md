# 范围与排期纪律（inspection-scope-discipline）

## 这个技能解决什么

定制单最容易死在"顺手多做一个功能"上：范围一涨，验收口径就漂，最后交付的东西没人能一口说清"这是什么"。
本技能把本单的**禁令**与**越界信号**写成可执行的判定步骤，并给出把待办排序、按剩余时间冻结的做法。

## 什么时候用

- 有人提出一个新想法 / 新需求 / "顺手加一下"时；
- 待办太多、需要在有限时间里排序时；
- 代码冻结前复核"还有没有越界的东西混进来了"。

**不要**用在本单之外的项目（这些禁令是本单的约定，不是通用法则）。

## 判定步骤（一问一答，逐条走）

对每一个待做的改动，按顺序问：

1. **它能对上模块一给的 16 个能力词之一吗？**（逐字对，不许同义替换）
   - 对不上 → 不做，记进"不做清单"。
2. **它触碰下面任何一条禁令吗？**（碰到就停）
   - ① **不做部署**：任何与部署/上线/发布流水线相关的东西都不做；
   - ② **不做账号 / 登录 / 权限体系**：角色只是演示用的视图切换，没有用户体系、没有权限矩阵、不持久化"身份"；
   - ③ **不做门店增删改**：只有两家示例门店的静态档案；
   - ④ **不做勾选表**：店长端入口**只有**非结构化输入（照片 + 一句话）；
   - ⑤ **禁止 if-else / 关键词规则兜底伪造模型判断**：判断只能来自真实模型调用；
   - ⑥ **模糊照片必须回"看不清"**：不许为了方便演示而硬编一个结论；
   - ⑦ **不许扩成「连锁公司管理系统」**：总部、组织架构、多门店排班这类一律不做。
3. **它需要新依赖吗？** 优先零第三方；必须引入时先确认本地可解析，解析不到就列为缺失并说明，**不静默降级**。
4. **它会让"一句话说明这是什么"变长吗？** 会 → 拆出去或砍掉。
5. **现在还做得了吗？** 按下面的时间纪律判断。

## 时间纪律（代码冻结倒计时，**每次按当前时间重算**）

- 冻结线以本单开工时刻为起点、**约 27 小时 50 分**为初始预算；**每轮开始前用当前时间重算剩余量**，不要把初始数字当成常驻事实。
- 剩余时间 ≥ 12 小时：可以做"能力词直接对应 + 有验收判据"的事。
- 剩余 4-12 小时：**只修不增**——只处理验收会失败的缺陷，不加功能。
- 剩余 < 4 小时：冻结代码，只写文档、补测试结果表、跑收尾自检。
- 任何"看起来很好但不在能力词里"的想法 → 一律记进"不做清单"，本轮不实现。

## 优先级排序（同样是逐条问）

1. **会阻断演示链路的缺陷**（例：模型调不通、路由没注册、重置把日志清了）——最高。
2. **验收会直接判 fail 的项**（能力词命中不了、工具名非法、`keywords` 少了词）。
3. **演示要用的四态样例**（达标/问题/逾期/看不清）——没有它现场演不完整。
4. **文档与测试结果表**（交付必需，但不阻塞跑通）。
5. **美化、体验、锦上添花** —— 本轮不做（美术层归后续环节）。

## 越界信号识别法（出现这些句子就该停下来）

- "顺手把 X 也做了吧" / "反正都写了，再加一个 Y" / "客户可能还想要 Z"；
- "先写死几条判断，演示的时候能看出来效果"（→ 触碰禁令 ⑤）；
- "这张照片看不清，就先当它是干净的"（→ 触碰禁令 ⑥）；
- "加个登录页显得完整"（→ 触碰禁令 ②）；
- "把门店管理做成增删改更实用"（→ 触碰禁令 ③）；
- "把检查项做成表格让店长勾选更快"（→ 触碰禁令 ④）。

遇到就回到判定步骤第 1 步，把它对回能力词；对不上就记进"不做清单"。

## 边界与不做什么

- 本技能本身是**技能**，**不得做成插件**（它是构建期纪律，客户与评委都看不见，也不该被工具调用）。
- 不做排期看板界面、不做自动化进度追踪工具。
- 不写成空话：上面每条判定都要给出"做 / 不做 / 延后"的明确结论与理由。
